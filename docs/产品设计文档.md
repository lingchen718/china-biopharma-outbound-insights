## 2. 背景与目标

### 2.1 背景

中国生物医药企业正在密集地将管线资产授权给海外公司，交易类型、金额、技术平台与治疗领域高度多元。现有数据以 Excel/CSV 形式存在，适合做数据治理，但不足以支撑“情报级”的浏览、检索与市场分析。

### 2.2 产品愿景

从一张交易清单，升级为一个**专业投资研究/行业情报平台**：用户既能快速回答“发生了什么交易”，也能层层下钻回答：

- 哪些**药物类型 / 技术路线**（Modality）正在获得国际关注；
- 哪些**治疗领域**（Therapeutic Areas）最活跃；
- 哪些**公司**在持续参与交易；
- 中国生物医药资产主要出海到哪些**授权区域**（Destination of Chinese biopharma assets）。

### 2.3 产品目标（MVP）

将 CSV 数据可靠导入 PostgreSQL，建立统一的维度与指标口径，并提供一个暗色、专业、可交互的分析平台。

分析页面按 3 个维度组织为 7 个栏目：

| 维度 | 栏目 |
| --- | --- |
| 市场分析 | 01 市场概览 Market Overview |
| 市场分析 | 02 交易格局 Deal Landscape |
| 市场分析 | 03 交易金额 Deal Economics |
| 交易内容分析 | 04 技术与管线 Modality & Pipeline |
| 交易内容分析 | 05 治疗领域 Therapeutic Areas |
| 交易内容分析 | 06 交易参与方 Companies |
| 数据检索 | 07 交易数据库 Transaction Explorer |

> 生态网络（Network）不再单列导航，而是**并入「06 交易参与方 Companies」**，作为一个独立的大方块（block）展示。

**推荐导航方案（中英文对照 + 一句话定位）**

- **01 市场概览 · Market Overview** —— 市场近期表现、关键事件、核心指标与重要信号。
- **02 交易格局 · Deal Landscape** —— 交易类型、交易方向、地区、阶段及结构分布。
- **03 交易金额 · Deal Economics** —— 首付款、里程碑付款、交易总额、披露率及金额分布。
- **04 技术与管线 · Modality & Pipeline** —— 药物形式、作用机制、靶点、研发阶段与技术热度。
- **05 治疗领域 · Therapeutic Areas** —— 肿瘤、自免、代谢、神经等领域的交易活跃度与趋势。
- **06 交易参与方 · Companies** —— 买方、卖方、授权方、被授权方及其交易记录与生态网络。
- **07 交易数据库 · Transaction Explorer** —— 按公司、资产、靶点、日期、交易类型等条件检索单笔交易。

### 2.4 非目标（Non-goals）

MVP 只做“已清洗 CSV → 平台”，不替代采集与清洗系统；不做实时行情、新闻流；不做用户账户与复杂权限（首版只读）。

### 2.5 未来升级方向（由 Non-goals 升级而来）

以下内容暂不在 MVP 范围，但作为明确的后续升级目标：

1. 接入原始采集/清洗流水线，形成“采集 → 治理 → 展示”闭环。
2. 增加实时新闻流与关键事件提醒。
3. 增加用户账户、收藏、订阅与权限体系。
4. 增加“2021 → 2026”动画时间轴叙事视图（作为次级故事线，而非精确分析主界面）。
5. 增加导出能力（CSV / Excel / PDF 报告）。

### 2.6 目标用户

- 生物医药 BD / 交易研究者
- 投资机构与二级市场研究员
- 药企战略与管线规划人员

## 3. 数据源与数据模型

### 3.1 源数据概况

- 当前样例：`cleaned_data_2021.csv`（53 条记录，覆盖 2021 年）。
- 目标覆盖：**2019–2026 YTD**（需接入 2019、2020 及 2022–2026 清洗结果）。
- 一行 = 一笔交易（deal），以 `deal_id` 为唯一键。
- 金额已有归一化字段：`upfront_musd`、`total_value_musd`（单位：百万美元，M USD）。

### 3.2 术语对照（中英文 + 平台口径）

| 英文字段/概念 | 中文口径 | 平台中的含义 |
| --- | --- | --- |
| Modality | **药物类型 / 技术形式** | 交易资产的技术平台（ADC、双抗、单抗、小分子、细胞疗法等） |
| Indication | **治疗领域**（Therapeutic Areas） | 交易面向的疾病领域（肿瘤、自免、代谢、神经等） |
| Stage | **研发阶段**（Asset Stage） | 签约时资产所处的研发成熟度 |
| Deal Type | 交易类型 / 交易结构 | 许可、合作开发、资产转让、并购、合资等 |
| Territory | **授权区域**（具体国家/地区） | 交易发生的具体目的地国家/地区 |
| Region | 区域（上层汇总） | 用于上层区域聚合与筛选的桶 |
| Upfront | 首付款 | 交易启动时支付的金额 |
| Total Value | 潜在总额 | 首付款 + 里程碑等构成的潜在总价值 |

### 3.4 关键数据问题与口径（需在 ETL 阶段解决）

1. **金额不能简单求和 `total_value`**：必须区分三套口径——
   - 已披露首付款 `SUM(upfront_musd)`
   - 里程碑合计 `SUM(milestone_musd)`
   - 潜在总额 `SUM(total_value_musd)`
2. **未披露 ≠ 0**：`value_disclosure` 含“未披露/N.A.”的记录不计入金额求和；“明确为 0”与“未披露”必须区分。
3. **里程碑数值口径**：仅当以下条件同时成立时，`milestone_musd = total_value_musd − upfront_musd`：
   - 两个金额对应同一笔交易、同一对价范围；
   - 币种与汇率换算口径一致；
   - 潜在总额包含首付款；
   - 两个数值均已披露；
   - 不存在无法拆分的股权或其他对价，且结果具有合理经济含义。
   否则标记为 **Not Derivable**，不强行生成里程碑金额。
4. **交易类型分类不一致**：需求文本的交易类型（License-out / China rights / Distribution / Asset transfer / M&A / JV）与 CSV 实际枚举（独占许可 / 合作开发 / 资产转让 / 非独占许可 / 期权协议 / 其他）不一致。建议建立“交易结构 + 交易方向”两级分类。
5. **药物形式/治疗领域中英混杂**：需规范化为英文枚举（用于稳定配色与筛选），中文作为显示别名。
6. **`territory` 多值**：需拆分为多对多关系；**世界地图按 `territory` 粒度展示具体国家/地区，`region` 用于上层区域汇总与筛选**。
7. **当前仅 2021 年数据**：产品目标 2019–2026，需接入 2019、2020 及后续年份，schema 向前兼容。
8. **阶段归类规则**：单资产用签约时阶段；多资产核心资产用 Lead Asset Stage；无核心资产标 `Multiple Stages`；未知标 `Unknown`，不默认为临床前。

### 3.5 PostgreSQL 数据模型（建议）

采用“事实表 + 维度表 + 桥接表”的星型/雪花结构。

```
companies          assets              deals（事实表）
──────────────     ──────────────      ──────────────────────────────
id (PK)            id (PK)             deal_id (PK)
name                drug_name           announce_date
name_en             drug_name_en        licensor_id  → companies
country             target              licensee_id  → companies
region              modality            asset_id     → assets
is_chinese          indication          deal_type
aliases             latest_stage        stage
                                       upfront_musd
deal_territory（桥接表）                milestone_musd (可为 Not Derivable)
───────────────────────────             total_value_musd
deal_id (FK)                           value_disclosure
territory                              confidence
region                                 currency, fx_rate
                                       territory_raw
                                       source_name, source_title
                                       source_url, publish_date
                                       analyst_note
                                       ingest_batch, created_at
```

- **`companies`**：licensor 与 licensee 统一入表，用 `is_chinese` 区分中国/海外。
- **`assets`**：资产与管线维度，支撑“药物形式 × 靶点 × 治疗领域”分析。
- **`deals`**：事实表，保存归一化金额与全部交易属性。
- **`deal_territory`**：把逗号分隔的 `territory` 拆成多行（国家/地区粒度），支撑地图展示与筛选。
- **参考表**：`modality`、`indication`、`stage`、`deal_type` 集中维护**英文规范名、中文别名、排序权重、固定配色**。

### 3.6 ETL 流程（Python）

```
CSV（已清洗）
   │  1. 读入 + 字段校验（26 列）
   ▼
清洗/规范化
   │  2. 规范 modality / indication / stage / deal_type 枚举
   │  3. 拆分 territory → 多行桥接表（国家/地区粒度）
   │  4. 金额归一化校验（currency × fx_rate → M USD）
   │  5. 派生 milestone_musd（仅满足 3.4 条件时；否则 Not Derivable）
   ▼
PostgreSQL upsert
   │  6. deal_id 幂等写入，记录 ingest_batch / created_at
   ▼
数据质量报告
      7. 披露率、置信度分布、缺失值、source_url 校验结果
```

## 7. 页面设计

### 7.1 市场概览（01 Market Overview）

**目的**：一屏回答“市场近期表现、关键事件、核心指标与重要信号”。

**KPI 卡片（首屏一行）**：

| KPI | 计算 |
| --- | --- |
| Total Deals | `COUNT(*)` |
| Total Disclosed Deal Value | `SUM(total_value_musd)`（仅披露） |
| Highest Deal Value | `MAX(total_value_musd)` |
| Chinese Licensors | `COUNT(DISTINCT licensor_id)` |
| Overseas Counterparties | `COUNT(DISTINCT licensee_id)` |
| Assets Involved | `COUNT(DISTINCT asset_id)` |

**页面模块**：
- KPI 卡片行
- 交易活跃度趋势（2019→2026，支持“指标 × 维度”切换）
- **全球足迹 / Destination of Chinese Biopharma Assets**（按 `territory` 国家/地区展示，点击国家 → 以 `region` 全局筛选）
- 最近交易（表格）

> 首屏**不再展示** Deal Type Mix 与 Modality Evolution，避免与其他导航栏目交叉重合。

### 7.2 交易格局（02 Deal Landscape）

**核心问题**：跨境创新药交易主要集中在哪里？市场在交易数量和资金投入上分别呈现什么结构？

**设计定义**：在选定年份下，从**研发阶段（Asset Stage）、药物形式（Modality）、治疗领域（Disease Area）、交易类型（Deal Type）**四个维度，分析交易的数量分布与首付款金额分布。

**每个维度配置一对环形图**：
- 左图：Counts of Deals by [维度]
- 右图：Sum of Upfront Payments (US$) by [维度]

**图表中心只突出与该图对应的总量**（数字 + Deals / Total Upfront），让用户立即理解每张图的分母。

**金额占比口径**：金额占比的分子与分母**只统计已披露首付款的交易**；未披露首付款不计入金额占比。每张金额图同时显示“已披露金额覆盖率”，例如 `Upfront disclosed for 72% of deals`。

**Key Insight**：每个分类维度图表下方自动生成轻量洞察：
- 交易数量占比最高的类别；
- 首付款金额占比最高的类别；
- 数量占比与金额占比差距最大的类别。

> 示例：`Phase II accounts for 20% of deals but 35% of disclosed upfront payments.`

### 7.3 交易金额（03 Deal Economics）

**目的**：回答“交易的经济价值如何？”核心原则——**避免平均值误导、区分首付款与潜在总额、处理金额披露不完整**。

**页面结构**（按“整体金额情况 → 金额分布 → 单笔交易探索 → 披露质量 → 里程碑分析”组织）：

1. **Market Value Snapshot**：首付款笔数及覆盖率、Total disclosed upfront、**Median upfront**、潜在总额笔数及覆盖率。顶部**不放金额总和**主导，而是“中位数 + 样本量 + 披露率 + 总额”共同出现。
2. **Deal Value Distribution**：按药物形式分组的金额箱线图（主指标 Total Potential Value，展示 P25/Median/P75 与离群点；最小值/最大值放入 Hover）。
3. **Deal Economics Explorer（交易气泡图）**：
   - 副标题：`Explore how deal economics vary by asset stage, modality and deal structure.`
   - X 轴：研发阶段（Preclinical → Phase I → II → III → Registration → Marketed，`Multiple Stages` 与 `Unknown` 置于末尾，可用筛选隐藏，并做轻微 jitter）；
   - Y 轴：潜在总额 `total_value_musd`（对数刻度）；
   - 气泡**面积**：首付款 `upfront_musd`（面积映射而非半径，设置 $1M/$10M/$100M 大小图例）；
   - 颜色：药物形式（固定配色）；
   - 形状：交易类型；
   - 每个气泡 = 一笔去重交易（稳定 `transaction_id`），点击进入 Explorer 对应详情；
   - Hover 分三层：交易识别（买卖方/资产/日期）→ 经济条款（首付款/潜在总额/里程碑/披露状态）→ 交易背景（药物形式/阶段/治疗领域/方向/区域）。
4. **Value Disclosure**：Upfront / Total Value / Milestone 三类披露率，及 Full / Partial / Undisclosed 状态笔数分布。
5. **Milestone Analysis**：`Largest Disclosed Milestone Packages` 榜单与区间分布；无法拆分股权/分成等对价的交易标记为 **Not Derivable**，不强行计算里程碑金额。

### 7.4 技术与管线（04 Modality & Pipeline）

**目的**：回答“哪些技术平台和研发阶段值得关注？”

**三个模块**：
- **Technology Trends**：ADC、双抗、细胞与基因疗法、小分子等药物形式的年度变化，推荐趋势折线图。
- **Target & Mechanism**：热门靶点、作用机制、技术组合，推荐排名 + 热度矩阵。
- **Asset Pipeline**：代表性资产的研发阶段、临床进展与交易事件，推荐资产表格 / 管线卡片。

> 区分价值：Deal Landscape 只回答“各阶段占多少交易”，本页进一步回答“ADC 交易集中在哪个阶段”“某靶点是否从临床前向临床推进”“哪些技术拥有更多进入临床后期的资产”。
> **注意**：交易数量 ≠ 临床成功率，不能仅凭交易量增加得出研发成功率更高的结论。

### 7.5 治疗领域（05 Therapeutic Areas）

**目的**：从“领域占比”深入到“领域内发生了什么”，回答“哪些治疗领域和具体适应症正在变化”。

**三个模块**：
- **Area Trends**：不同治疗领域的年度交易数量与金额变化（趋势图）。
- **Indication Hotspots**：各领域内热门具体适应症（排名 + 适应症分布）。
- **Area Deep Dive**：单个领域的药物形式、阶段、公司、交易分析（联动筛选面板）。

> 例：Oncology 下钻到 ADC/双抗/细胞疗法及肺癌、乳腺癌、卵巢癌等；Metabolic Diseases 下钻到肥胖、糖尿病等。

### 7.6 交易参与方（06 Companies）

**目的**：回答“谁在做交易？生态网络如何？”

**模块**：
- 中国授权方排行榜（交易笔数 / 披露总额 / 中位数 / 药物形式数 / 治疗领域数，多指标可切换排序）。
- 海外对手方排行榜（同上）。
- 公司 × 药物形式气泡图（点击打开公司档案）。
- **生态网络（Network）——独立大方块**：节点=公司（中国/海外颜色区分），边=交易，节点大小=笔数，边粗细=金额或笔数；点击节点查看公司档案。

### 7.7 交易数据库（07 Transaction Explorer）

**目的**：最核心的功能组件——完整可检索交易表 + 交易详情。

**过滤器**：公司 / 资产 / 靶点 / 日期 / 交易类型 / 药物形式 / 治疗领域 / 阶段 / 区域 / 披露状态。

**结果表**：Date | 中国授权方 | 海外对手方 | 资产 | 药物形式 | 治疗领域 | 阶段 | 交易类型 | 首付款 | 潜在总额。点击行打开交易卡片。

## 8. 指标与计算口径（Methodology）

> 核心原则：**金额分口径、未披露不求和、用分布不用均值、区分“披露为 0”与“未披露”。**

| 指标 | 计算口径 | 单位 | 备注 |
| --- | --- | --- | --- |
| 交易笔数 Total Deals | `COUNT(DISTINCT deal_id)` | 笔 | 所有记录 |
| 已披露首付款 Upfront | `SUM(upfront_musd)`（非空） | M USD | 披露子集 |
| 中位数首付款 Median Upfront | `PERCENTILE_CONT(0.5)`（非空） | M USD | **顶部关键指标** |
| 里程碑 Milestones | `SUM(milestone_musd)`（Derivable 且非空） | M USD | 不满足条件为 Not Derivable |
| 潜在总额 Total Potential Value | `SUM(total_value_musd)`（非空） | M USD | 披露子集 |
| 最高单笔 Highest Deal | `MAX(total_value_musd)` | M USD | — |
| 中国授权方数 | `COUNT(DISTINCT licensor_id)` | 家 | — |
| 海外对手方数 | `COUNT(DISTINCT licensee_id)` | 家 | — |
| 涉及资产数 | `COUNT(DISTINCT asset_id)` | 个 | — |
| 覆盖区域数 | `COUNT(DISTINCT region)` | 个 | — |
| Upfront Disclosure Rate | 首付款已知笔数 ÷ 总笔数 | % | 披露率反映“是否可知”，非“是否>0” |
| Total Value Disclosure Rate | 潜在总额已知笔数 ÷ 总笔数 | % | — |
| Milestone Disclosure Rate | 里程碑已知笔数 ÷ 总笔数 | % | — |

**金额单位**：统一以 M USD 存储；展示层 ≥ 1000 时显示 `$X.XB`，其余 `$X M`。

**披露状态处理**：参与笔数统计，但不参与金额求和；“明确为 0”与“未披露”分开，金额图标注覆盖率。

## 10. 非功能需求

- **性能**：任意页面首屏 < 2s；聚合下推到 PostgreSQL。
- **响应式**：桌面优先，平板可用。
- **可访问性**：暗色主题下对比度满足 WCAG AA，颜色之外辅以标签/图例。
- **可分享**：过滤状态写入 URL。
- **数据可追溯**：交易详情可见信源链接、发布日期、置信度与分析师备注。

## 11. 数据质量与治理

- ETL 输出数据质量报告：总笔数、披露率、置信度分布、缺失字段、`source_url` 校验失败数。
- `confidence=low` 或 404 链接在明细页显著标注。
- `ingest_batch` / `created_at` 支持导入审计与回滚。
- 枚举一致性检查：新增值进入 lookup 表后才入库。
- 披露状态按数据库字段定义 Full / Partial / Undisclosed，不凭首付款是否有值判断。

### 14.2 枚举规范化参考（基于 2021 样例 + 全周期目标）

- **Modality（药物类型/技术形式）**：ADC、Bispecific、Monoclonal antibody (mAb)、Small molecule、CAR-T/Cell therapy、Peptide/Protein、Vaccine、Other。
- **Indication（治疗领域）**：Oncology、Autoimmune、CNS、Metabolic、Infectious、Rare disease、Vaccine、Other。
- **Stage（研发阶段，有序）**：Preclinical → IND approved → Phase I → Phase II → Phase III → Registration → Marketed（另加 Multiple Stages、Unknown 置于末尾）。
- **Deal Type（交易类型）**：Exclusive license、Co-development、Asset transfer/Assignment、Non-exclusive license、Option agreement、M&A、JV、Other。
- **Confidence**：high / medium / low。
