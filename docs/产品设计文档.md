## 2. 背景与目标

### 2.1 背景

中国生物医药企业正在密集地将管线资产授权给海外公司，交易类型、金额、技术平台与治疗领域高度多元。现有数据以 Excel/CSV 形式存在，适合做数据治理，但不足以支撑“情报级”的浏览、检索与市场分析。

### 2.2 产品愿景

从一张交易清单，升级为一个**专业投资研究/行业情报平台**：用户既能快速回答“发生了什么交易”，也能层层下钻回答“哪些技术、哪些适应症、哪些公司，以及主要吸引哪些地区的国际资本”。

### 2.3 产品目标（MVP）

- 将 CSV 数据可靠地导入 PostgreSQL，并建立统一的维度与指标口径。
- 提供 6–8 个分析页面，覆盖总览、格局、金额、技术与管线、治疗领域、公司与对手方、交易检索、生态网络。
- 支持全局过滤器 + 跨页面联动下钻（点击某一地区/公司/模态 → 全局过滤）。
- 所有图表可切换“指标 × 维度”，支持按披露状态、置信度分层查看。
- 保持“生物科技/投资研究”的视觉风格，分类色全站一致。

### 2.4 非目标（Non-goals）

- 不替代交易数据库的采集与清洗系统（MVP 只负责“已清洗 CSV → 平台”）。
- 不做实时市场行情、股价或新闻流。
- 不做用户账户体系与复杂权限（首版只读，面向内部/研究用户）。
- 动画时间轴仅作为**辅助叙事元素**，不构成精确分析主界面。

### 2.5 目标用户

- 生物医药 BD / 交易研究者
- 投资机构与二级市场研究员
- 药企战略与管线规划人员

## 3. 数据源与数据模型

### 3.1 源数据概况

- 当前样例：`cleaned_data_2021.csv`（53 条记录，覆盖 2021-01-12 至 2021-12-30）。
- 目标覆盖：2021–2026 YTD（需后续接入 2022–2026 清洗结果）。
- 一行 = 一笔交易（deal），以 `deal_id` 为唯一键。
- 金额已有归一化字段：`upfront_musd`、`total_value_musd`（单位：百万美元，M USD）。

### 3.2 源数据字段字典（26 列）

| # | CSV 字段 | 类型 | 示例 | 说明 / 平台用途 |
| --- | --- | --- | --- | --- |
| 1 | `deal_id` | string | `2021-BeiGen-Novart-e682e18d` | 唯一主键 |
| 2 | `announce_date` | date | `2021-01-12` | 公告日期，时间序列 x 轴 |
| 3 | `licensor` | string | `百济神州 BeiGene` | 中国授权方，公司维度 |
| 4 | `licensee` | string | `Novartis` | 海外对手方，公司维度 |
| 5 | `drug_name` | string | `Tislelizumab 替雷利珠单抗` | 资产/管线名称 |
| 6 | `target` | string | `PD-1` | 靶点，资产维度 |
| 7 | `modality` | string | `单抗（非ADC）Monoclonal antibody` | 模态（需做英文规范化） |
| 8 | `indication` | string | `肿瘤 Oncology` | 治疗领域（需做规范化） |
| 9 | `deal_type` | string | `独占许可 Exclusive license` | 交易结构 |
| 10 | `stage` | string | `III期 Phase III` | 研发阶段（有序枚举） |
| 11 | `upfront` | number | `650.0` | 首付款原始金额（按原币种） |
| 12 | `total_value` | number | `2200.0` | 潜在总额原始金额 |
| 13 | `value_disclosure` | string | `金额全披露·分成未披露 Amounts disclosed, royalty not disclosed` | 披露状态 |
| 14 | `milestones` | string | `up to 1550 M USD (milestone payments)` | 里程碑（源为文本；数值由 total_value_musd − upfront_musd 派生） |
| 15 | `territory` | string | `US, Canada, Mexico, EU, UK, ...` | 授权地区（多值，逗号分隔） |
| 16 | `source_name` | string | `Reuters` | 信源名称 |
| 17 | `source_title` | string | `BeiGene, Novartis partner ...` | 信源标题 |
| 18 | `publish_date` | date | `2021-01-12` | 信源发布日期 |
| 19 | `analyst_note` | string | 长文本 | 分析师备注/核查说明 |
| 20 | `confidence` | string | `high / medium / low` | 数据可信度 |
| 21 | `region` | string | `全球 Global` | 归一化地区桶（分析维度） |
| 22 | `currency` | string | `USD` | 原币种 |
| 23 | `source_url` | string | URL | 信源链接（可跳转/校验） |
| 24 | `fx_rate` | number | `1.0` | 汇率（USD 为 1.0） |
| 25 | `upfront_musd` | number | `650.0` | **归一化首付款（M USD）** |
| 26 | `total_value_musd` | number | `2200.0` | **归一化潜在总额（M USD）** |

> 字段单位说明：**口径以 CSV 实际字段为准**，统一使用 `upfront_musd` / `total_value_musd`（单位：百万美元，M USD）。全站金额均以 M USD 存储与计算。

### 3.3 关键数据问题与口径（需在 ETL 阶段解决）

1. **金额不能简单求和 `total_value`**：必须区分三套口径——
   - 已披露首付款 `SUM(upfront_musd)`
   - 里程碑合计 `SUM(milestone_musd)`（由 `total_value_musd − upfront_musd` 派生）
   - 潜在总额 `SUM(total_value_musd)`
2. **未披露金额不计入求和**：`value_disclosure` 含 `未披露或不适用 Undisclosed / N/A` 等状态，求和时剔除，另以“披露笔数 / 披露率”呈现。
3. **置信度分层**：`confidence = high / medium / low`，关键金额类指标应支持按置信度过滤或标注。
4. **里程碑数值口径**：`milestone_musd = total_value_musd − upfront_musd`（当首付款与总额均已披露时派生）；源字段 `milestones` 文本保留用于详情展示与审计，不做数值解析。仅当两端之一缺失时，里程碑数值为空；若派生结果为负（total < upfront），标记为数据异常并在质量报告中复核，不计入里程碑求和。
5. **交易类型分类不一致**：需求文本的交易类型（License-out / China rights / Distribution / Asset transfer / M&A / JV）与 CSV 实际枚举（独占许可 / 合作开发 / 资产转让 / 非独占许可 / 期权协议 / 其他）不一致。建议建立两级分类（见 3.4）。
6. **模态/适应症中英混杂**：需规范化为英文枚举（用于稳定配色与筛选），中文作为显示别名。
7. **`territory` 多值**：需拆分为多对多关系，才能做“点击美国 → 全局过滤”的地理分析。
8. **当前仅 2021 年数据**：产品目标 2021–2026，需保证 schema 对后续年份向前兼容。

### 3.4 PostgreSQL 数据模型（建议）

采用“事实表 + 维度表 + 桥接表”的星型/雪花结构，兼顾查询性能与维度复用。

```
companies          assets              deals（事实表）
──────────────     ──────────────      ──────────────────────────────
id (PK)            id (PK)             deal_id (PK)
name                drug_name           announce_date
name_en             drug_name_en        licensor_id  → companies
country             target              licensee_id  → companies
region              modality            asset_id     → assets
is_chinese          indication          deal_type
aliases             latest_stage        stage
                                       upfront_musd
deal_territory（桥接表）                milestone_musd
───────────────────────────             total_value_musd
deal_id (FK)                           value_disclosure
territory                              confidence
region                                 currency, fx_rate
                                       territory_raw
                                       source_name, source_title
                                       source_url, publish_date
                                       analyst_note
                                       ingest_batch, created_at
```

- **`companies`**：licensor 与 licensee 统一入同一张表，用 `is_chinese` 区分中国/海外，支撑网络图“节点颜色 = 中国/非中国”。
- **`assets`**：资产与管线维度，支撑“模态 × 靶点 × 适应症”分析。
- **`deals`**：事实表，保存归一化金额与全部交易属性。
- **`deal_territory`**：把逗号分隔的 `territory` 拆成多行，支撑世界地图与地区过滤。
- **参考表**：`modality`、`indication`、`stage`、`deal_type` 建议建 lookup 表，集中维护**英文规范名、中文别名、排序权重、固定配色**，保证全站颜色一致。

### 3.5 ETL 流程（Python）

```
CSV（已清洗）
   │  1. 读入 + 字段校验（26 列）
   ▼
清洗/规范化
   │  2. 派生 milestone_musd = total_value_musd − upfront_musd（两端披露时）
   │  3. 规范 modality / indication / stage / deal_type 枚举
   │  4. 拆分 territory → 多行桥接表
   │  5. 金额归一化校验（currency × fx_rate → M USD）
   ▼
PostgreSQL upsert
   │  6. deal_id 幂等写入，记录 ingest_batch / created_at
   ▼
数据质量报告
      7. 披露率、置信度分布、缺失值、source_url 校验结果
```

ETL 必须**幂等**（同一 `deal_id` 可重复导入），并输出数据质量报告，供平台“数据质量”页或后台查看。

## 4. 技术架构

```
                     ┌──────────────────────────────┐
                     │        Next.js 前端           │
                     │   SSR + 客户端交互式图表       │
                     │   （页面 / 组件 / 过滤器）      │
                     └──────────────┬───────────────┘
                                    │ API（REST / tRPC）
                     ┌──────────────▼───────────────┐
                     │    应用服务 / 查询层           │
                     │  聚合查询 · 过滤 · 指标计算     │
                     └──────────────┬───────────────┘
                                    │ SQL
                     ┌──────────────▼───────────────┐
                     │        PostgreSQL             │
                     │  deals / companies / assets   │
                     │  deal_territory / lookup      │
                     └──────────────▲───────────────┘
                                    │ upsert
                     ┌──────────────┴───────────────┐
                     │      Python ETL（离线）        │
                     │  清洗 · 规范化 · 幂等导入       │
                     └──────────────▲───────────────┘
                                    │
                              CSV（已清洗）
```

- **存储**：PostgreSQL 为首选；如后续数据量/多租户分析需求上升，可评估 Snowflake / BigQuery，但 MVP 不引入。
- **前端**：Next.js；图表建议使用可交互、支持大数据的库（如 ECharts / Recharts / Plotly / D3），地图使用 GeoJSON 世界地图。
- **后端处理**：Python 负责离线 ETL；在线聚合优先下推到 SQL，避免前端全量拉数。
- **交互模式**：全局过滤器通过 URL 查询参数（`?period=&modality=&region=...`）持久化，保证可分享、可回退。

## 6. 全局交互与过滤器

### 6.1 全局过滤器（所有分析页共用）

- **Period（年份）**：`2021 ─ 2026` 区间滑块
- **Deal Type（交易结构）**：License-out / 合作开发 / 资产转让 / 非独占 / 期权 / M&A / JV / 其他
- **Modality（模态）**：ADC / Bispecific / mAb / Small molecule / CAR-T / Peptide / Vaccine / 其他
- **Indication（治疗领域）**：Oncology / Autoimmune / CNS / Metabolic / Infectious / Rare disease / 其他
- **Stage（阶段）**：Preclinical / IND / Phase I / II / III / Registration / Marketed
- **Region / Territory（地区）**：US / Europe / Japan / APAC / Emerging Markets / Global / 其他

> 所有页面共享同一套过滤状态，任一图表下钻（如点击“美国”）都会回写全局过滤条件，形成“点地图 → 全站联动”的体验。

### 6.2 核心交互原语

| 交互 | 说明 |
| --- | --- |
| 指标切换 | 趋势图可在“笔数 / 首付款 / 潜在总额”之间切换 |
| 维度切换 | 趋势图可在“模态 / 适应症 / 阶段 / 地区”之间切换 |
| 点击下钻 | 点击柱、扇区、地图区域、表格行 → 过滤全局并展开明细 |
| 交易卡片 | 点击任意交易行 → 弹出“Deal Card”详情 |
| 排序 | 排行榜支持按笔数 / 总金额 / 中位数 / 模态数 / 适应症数切换 |

## 7. 页面设计

### 7.1 总览页（01 Executive Overview / Market Overview）

**目的**：一屏回答“市场正在发生什么”。

**KPI 卡片（首屏一行）**：

| KPI | 计算 |
| --- | --- |
| Total Deals | `COUNT(*)` |
| Total Disclosed Deal Value | `SUM(total_value_musd)`（仅披露） |
| Highest Deal Value | `MAX(total_value_musd)` |
| Chinese Licensors | `COUNT(DISTINCT licensor_id)` |
| Overseas Counterparties | `COUNT(DISTINCT licensee_id)` |
| Assets Involved | `COUNT(DISTINCT asset_id)` |
| Countries / Regions | `COUNT(DISTINCT region)` |

> 首屏线框（来自需求，已对齐字段）：

```
┌───────────────────────────────────────────────────────────────┐
│ CHINA BIOPHARMA OUT-LICENSING DEAL INTELLIGENCE               │
│ 2021–2026 YTD                                                 │
│ [Period] [Deal Type] [Modality] [Indication] [Region]         │
├──────────┬──────────┬──────────┬──────────┬──────────┬───────┤
│  DEALS   │  VALUE   │ UPFRONT  │  ASSETS  │ CHINESE  │ GLOBAL│
│   482    │ $XX.XB   │  $X.XB   │   391    │   128    │  214  │
├─────────────────────────────────────┬─────────────────────────┤
│       DEAL ACTIVITY                 │     GLOBAL FOOTPRINT    │
│       2021 ──── 2026                │        WORLD MAP        │
├──────────────────────┬──────────────┴─────────────────────────┤
│ DEAL TYPE MIX        │ MODALITY EVOLUTION                     │
├──────────────────────┴────────────────────────────────────────┤
│ RECENT TRANSACTIONS                                            │
│ Date | Company | Partner | Asset | Modality | Deal | Value     │
└───────────────────────────────────────────────────────────────┘
```

**页面模块**：
- KPI 卡片行
- 交易活跃度趋势（2021→2026，支持“指标 × 维度”切换）
- 全球足迹世界地图（点击国家 → 全站过滤）
- 交易结构构成（饼/环形图）
- 模态演化（堆叠面积图）
- 最近交易（表格）

### 7.2 交易格局页（02 Deal Landscape）

**目的**：回答“都在发生哪类交易”。

**模块**：
- **阶段 × 交易结构矩阵**：行 = stage，列 = deal type，单元格强度/大小 = 交易笔数（用热力格或气泡大小表示）。
- **交易结构构成**：随时间堆叠面积图，看 License-out / 合作开发 / 资产转让 的结构变化。
- **交易结构排行榜**：按笔数、总金额、中位数金额切换。
- **地区分布**：region 维度交易笔数与金额对比。

### 7.3 交易金额页（03 Deal Economics）

**目的**：回答“这些交易值多少钱”，且**避免用平均值误导**。

**模块**：
- **金额分布箱线图**：按 modality 分组，展示 25/50/75 分位、最大/最小值（用 total potential value）。
- **首付款 vs 潜在总额**散点/气泡图（见 7.3.1 交易气泡图）。
- **披露状态统计**：`value_disclosure` 各状态笔数 + 金额披露率。
- **里程碑**：派生后的 `milestone_musd` 分布与 Top 榜单。

#### 7.3.1 交易气泡图（核心分析视图）

> 每个气泡 = 一笔交易。
> - X 轴：研发阶段（Pre → I → II → III → Registration → Marketed）
> - Y 轴：潜在总额 `total_value_musd`（对数刻度）
> - 气泡大小：首付款 `upfront_musd`
> - 气泡颜色：模态（固定配色）
> - 气泡形状：交易结构
> - Hover：公司 / 资产 / 对手方 / 日期 / 适应症 / 地区

这是全站**最有分析价值的单一视图**，用于快速发现高价值、早阶段、新模态交易。

### 7.4 技术与管线页（04 Modality & Pipeline）

**目的**：回答“哪些技术/阶段在吸引国际兴趣”。

**模块**：
- **模态演化堆叠面积/流图**：按年展示 ADC / Bispecific / mAb / Small molecule / CAR-T / RNA 等占比变化（需求特别要求“流图/堆叠面积图”而非普通热力图）。
- **阶段分布**：各阶段笔数与金额。
- **靶点 Top 榜**：按交易笔数/金额展示 `target`。
- **模态 × 阶段矩阵**：气泡大小 = 笔数。

### 7.5 治疗领域页（05 Therapeutic Areas）

**目的**：回答“活动集中在哪些疾病领域”。

**模块**：
- 适应症 Top 榜（笔数、金额、模态构成）。
- 适应症 × 模态 气泡图。
- 适应症 × 阶段 分布。
- 点击某适应症 → 过滤全站（与全局过滤器联动）。

### 7.6 公司与对手方情报页（06 Company / Counterparty）

**目的**：回答“谁在做交易”，且**不做武断排名**。

**两个排行榜**：

| 中国授权方排行 | 海外对手方排行 |
| --- | --- |
| 公司 / 交易笔数 / License-out / 模态数 / 治疗领域数 / 披露总额 | 公司 / 与中国交易笔数 / License-in / M&A / 模态数 / 金额 |

**排序维度（可切换）**：
- 交易笔数
- 披露总额
- 中位数金额
- 模态数量
- 治疗领域数量

## 8. 指标与计算口径（Methodology）

> 核心原则：**金额分口径、未披露不求和、用分布不用均值。**

| 指标 | 计算口径 | 单位 | 备注 |
| --- | --- | --- | --- |
| 交易笔数 Total Deals | `COUNT(DISTINCT deal_id)` | 笔 | 所有记录 |
| 已披露首付款 Upfront | `SUM(upfront_musd)`（仅 `upfront_musd` 非空） | M USD | 披露子集 |
| 里程碑 Milestones | `SUM(milestone_musd)`，其中 `milestone_musd = total_value_musd − upfront_musd`（两端披露时） | M USD | 派生字段 |
| 潜在总额 Potential Total Value | `SUM(total_value_musd)`（非空） | M USD | 披露子集 |
| 最高单笔 Highest Deal | `MAX(total_value_musd)` | M USD | — |
| 中国授权方数 Chinese Licensors | `COUNT(DISTINCT licensor_id)` | 家 | — |
| 海外对手方数 Overseas Counterparties | `COUNT(DISTINCT licensee_id)` | 家 | — |
| 涉及资产数 Assets | `COUNT(DISTINCT asset_id)` | 个 | — |
| 覆盖国家/地区 Regions | `COUNT(DISTINCT region)` | 个 | — |
| 中位数金额 Median | `PERCENTILE_CONT(0.5)` | M USD | 用于排行榜/箱线图 |
| 25/75 分位 | `PERCENTILE_CONT(0.25/0.75)` | M USD | 箱线图 |
| 披露率 Disclosure Rate | `披露金额笔数 / 总笔数` | % | 数据质量提示 |

**单位换算**：金额统一以 **M USD** 存储；展示层 ≥ 1000 时显示为 **$X.XB**（十亿美元），其余显示 **$X M**。

**披露状态处理**：`value_disclosure` 的“未披露或不适用”记录，参与笔数统计，但**不参与**金额求和；图表中需有“N 笔未披露”的标注。

**置信度处理**：金额类图表支持按 `confidence`（high/medium/low）过滤或着色提示；低置信度记录不应静默影响关键总额。

## 10. 非功能需求

- **性能**：任意页面首屏 < 2s；聚合查询下推到 PostgreSQL，前端只取聚合结果。
- **响应式**：桌面优先，表格/地图在平板可用。
- **可访问性**：颜色之外辅以标签/图例；对比度满足 WCAG AA。
- **可分享**：过滤状态写入 URL，链接可直接复现视图。
- **可回退**：所有筛选可一键清除。
- **数据可追溯**：每个交易详情必须可见信源链接、发布日期、置信度与分析师备注。

## 11. 数据质量与治理

- ETL 每次运行输出**数据质量报告**：总笔数、披露率、置信度分布、缺失字段、`source_url` 校验失败数。
- `confidence=low` 或 `source_url` 404 的记录，在明细页显著标注。
- 建立 `ingest_batch` 与 `created_at`，支持“某次导入”的回滚与审计。
- 建立枚举一致性检查：modality / indication / stage / deal_type 不得出现未登记的新值（新值进入 lookup 表后再入库）。
